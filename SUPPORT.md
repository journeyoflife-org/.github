# Support

How to get help with software in the `journeyoflife-org` organization. This file
is the organization-wide default and is linked from the community profile of
every repository that does not define its own `SUPPORT.md`.

## Who maintains this code

These repositories are operated by the engineering function of a charitable
mission organization, not by a commercial vendor. Support is best-effort and is
provided for the organization's own operational needs first; we are glad when
others find the code useful, but we cannot promise response times for outside
requests.

## Where to ask

| Situation | Channel |
|-----------|---------|
| Defect in code or configuration | Open an issue in the affected repository using the bug form |
| Enhancement or new capability | Open an issue in the affected repository using the feature form |
| Security vulnerability | **Not an issue.** Follow [SECURITY.md](SECURITY.md) — `security@journeyoflife.org` or a private security advisory |
| Which repository owns a problem | See the organization profile README for the repository map |
| Supporting the mission | [Donate](https://journeyoflife.org/donate) |

Blank issues are disabled so that reports arrive with the detail needed to
reproduce them. If no form fits, choose the closest one and say so in the body.

## Before opening an issue

1. Confirm the problem is reproducible against the current `main` branch.
2. Search existing issues, including closed ones.
3. State the repository, the commit or release, and the environment.
4. **Redact anything personal.** Do not paste parishioner, pilgrim, clergy or
   donor data, real identifiers, credentials, tokens or internal hostnames into
   an issue. This organization processes special category data under GDPR
   Article 9, and issues are public. Use synthetic values.

## Self-hosting

Documentation for operators lives in each repository, normally under `docs/`:
architecture decision records, runbooks and server notes. Where a repository
contains no operator documentation, it is not intended to be deployed outside
the organization's own estate.

## No support contract

There is no paid support tier, no service-level agreement for external users,
and no indemnity. The software is provided under the license stated in each
repository.
